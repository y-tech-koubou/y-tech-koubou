### MVP スコープ（公開可能な最小機能セット）

**含める**:
- ワークショップ一覧表示（公開済み）
- ワークショップ詳細表示（公開済み）
- 予約フロー（メールアドレス＋名前のみ。決済は手動振込）
- マイ予約一覧（キャンセル含む）

**MVPでは保留**:
- Stripe オンライン決済（Hugtime本体のStripe復旧待ち）

6. naoko 写真撮影（Hugtime HP の残タスクと連動）

### 公開時期目標

- Web版（Vercel）: 2026-06上旬

## 共通: 育苗中の運用方針

### 「焦らない」方針

3アプリは現在「土を整えている期間」として位置づけ、無理な公開は避ける。
architect-quiz の収益・ユーザー基盤が立ち上がってから順次着手する。

### 育苗中の最低メンテナンス

| 項目 | 頻度 |
|---|---|
| `npx tsc --noEmit` 確認 | 月1回 |
| Expo SDK アップグレード追従 | 半年に1回 |
| 依存パッケージのセキュリティアラート対応 | 即時 |
| README / CLAUDE.md の更新 | 機能追加時 |

### 共通の技術判断

- すべて Expo SDK 54 ベース（[[project_architect_quiz]] と統一）
- 認証は Firebase Auth（Google + Email/Password が標準）
- データストアは Firestore（オフライン同期の必要性に応じて検討）
- Web版は Vercel、モバイルは Expo Build → Store配信

### 順序付けの根拠

1. **koji-app** が最優先: 既に最も実装が進んでおり、Hugtime事業の中核
2. **invest-ai** が次: 自分自身がユーザーになれる（建築士勉強の合間に資産形成）
3. **africa-map** が最後: コンテンツ収集が継続的に必要、即金性が薄い

## architect-quiz 過去問拡充（ネット復活後）

過去問PDF（2016-2025の構造・法規・計画/設備、計30本）を `Desktop/Yテック工房/一級建築士/` に保管済み。
これらをテキスト抽出し、新規問題作成のソースとして活用する手順：

### 1. PDFツールインストール（2分）

```powershell
cd C:\Users\yoshino.takayuki\architect-quiz-expo
.\scripts\install-pdf-tools.ps1
```

ScoopとPoppler(pdftotext)が自動インストールされる。

### 2. PDF一括テキスト化（1分）

```powershell
.\scripts\extract-past-exams.ps1
```

`.past-exams-text/` 配下に `構造/`, `法規/`, `計画・設備/` で30個の .txt が出力される。
`.gitignore` に登録済みのため、過去問テキスト自体はコミットされない（著作権配慮）。

### 3. Claudeに問題作成を依頼

「過去問テキストから問題を追加して」と依頼すると、Claudeが：
- `.past-exams-text/` 配下のテキストを読み取り
- 出題傾向・頻出論点を分析
- 自作の〇×問題（問題文・解説とも自作）を `src/data/questions.ts` に追加
- 元の過去問は引用せず、論点だけを抽出する方針（`y-tech-koubou/BRAND.md` 準拠）

### 取り込み方針（確定済み）

- ✅ 過去問は「出題された論点」のリストとして参照
- ✅ 問題文は自作（自分の言葉で書き起こす）
- ✅ 解説は150〜250字で自作
- ❌ 過去問の原文をそのまま引用しない（著作権リスク回避）

理由: 既存questions.tsの方針「著作権物の引用を避け、教科書水準の事実から作成」と整合させるため。

### 想定追加問題数

過去問10年×3科目で、各年20〜25問×3=600〜750問の出題論点がある。
重複・既存カバーを除いて、純増300〜500問が見込める。
これにより既存1,435問+300〜500問で、約1,800〜2,000問規模になる。
